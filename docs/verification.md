# Verification

## 1. Results

All PTX paths report zero mismatches over the full input domain on three devices: A100 (sm_80), RTX 4060 Laptop (sm_89) and RTX PRO 5000 Blackwell (sm_120). Device, driver and CUDA toolkit versions, together with the per-group comparison totals, are in [`results/SUMMARY.md`](results/SUMMARY.md).

The 29 PTX paths comprise 12 minimal, 7 non-`.ftz` approx f32, 2 f16x2 and 8 correctly rounded paths; sm_120 adds 2 BF16 paths. The model library is platform-specific: `lib/libmufu_model.a` (ELF, Linux x86_64) and `lib/mufu_model.lib` (COFF, Windows). The RTX 4060 row uses the latter; its sha256 is in `lib/mufu_model.lib.sha256`.

## 2. Verification Method

Each input is evaluated on the GPU, which executes the corresponding PTX instruction, and on the CPU, which applies the `ptx/` wrapper and the `lib/` model. The two output bit patterns are compared on the host. The GPU output is the reference value; the model is evaluated as CPU machine code.

- Chunked pipeline in blocks of 2^23 inputs: CPU threads generate the inputs, the GPU executes PTX and returns the results, and CPU threads evaluate the model and compare, accumulating `checked` and `mismatch`.
- A path passes when `checked` equals the size of its input domain and `mismatch` is 0. `checked` is a host-side count; a count different from the domain size reports FAIL.
- All CPU cores are used by default; `SFU_THREADS=<n>` limits the thread count. Full-run time scales with the core count.
- On the first mismatch the program prints the `input / model / hardware` bit patterns.

## 3. CPU-only Checks

| Command | Description |
|---|---|
| `make selftest` | Check the `round_f32` and `f16x2` models against known inputs and outputs, and call the library directly |
| `make offline` | Replay the recorded A100 inputs and outputs in `test/offline/a100_sm80.tsv` line by line: 131,430 rows covering 12 paths |
| `make eval` | Build the query tool, for example `build/sfu_eval sqrt.rn.f32 0x40000000` |
| `make test` | `selftest` + `offline` |

These four commands are CPU-only; the `cpu-checks` CI job runs `make test`. The expected values of `offline` come from `test/offline/a100_sm80.tsv` shipped with the repository (131,430 recorded A100 outputs), not from a live measurement on the verifier's machine. The full-domain results of Section 1 are reproduced on a machine with an NVIDIA GPU following Sections 4 and 5. Equivalent native-Windows commands for hosts without CUDA are in Option C of [windows.md](windows.md).

## 4. GPU Checks

At run time each verifier checks that the GPU architecture matches the `ARCH` used at compile time and refuses to run on a mismatch.

| make target | Paths | Input domain per path | Last line |
|---|---|---|---|
| `gpu-negative` | `ex2.approx.ftz.f32` (plus BF16 EX2 on sm_120) | 65,536; the model output for input 0 is flipped to confirm that the comparator detects an error | `NEGATIVE CONTROL PASS` |
| `gpu-minimal-smoke` | 12 minimal paths (14 on sm_120) | 2^22 uniformly spaced inputs (all 65,536 for f16 / BF16) | `SMOKE PASS` |
| `gpu-minimal` | as above | f32: 2^32; f64: 2^32 high words with the low word fixed to zero; f16 / BF16: 65,536 | `PASS` |
| `gpu-extended-smoke` / `gpu-extended` | 7 non-`.ftz` approx f32 | 65,629 boundary values / 2^32 | `EXTENDED F32 [SMOKE] PASS` |
| `gpu-f16x2-smoke` / `gpu-f16x2` | `ex2/tanh.approx.f16x2` | 65,536 per half / 2^32 | `F16X2 [SMOKE] PASS` |
| `gpu-round-smoke` / `gpu-round` | `rcp/sqrt.rn/rz/rm/rp.f32` | 65,614 boundary values / 2^32 | `ROUND F32 [SMOKE] PASS` |

- `make gpu-all TAG=<name> ARCH=<sm_XX>` runs selftest, offline, the negative control, minimal, extended, f16x2 and round in sequence. Logs are written to `build/results/<TAG>_<ARCH>/`; `env.txt` records the device and toolchain; `summary.txt` holds one line per step; steps already passed are skipped on a rerun. `TAG` names the result directory.
- `ARCH` values: `sm_80` (A100), `sm_89` (RTX 40 series), `sm_120` (Blackwell, including 2 BF16 paths). A standalone `gpu-*` target defaults to `sm_80` when `ARCH` is omitted; `make gpu-all` detects the architecture automatically when `ARCH` is omitted.
- `gpu-round*` accepts `PATH_NAME=rcp.rn.f32` to run a single path.
- The surrounding SASS is generated by ptxas and depends on the architecture and toolchain. The results for each device correspond to the toolchain recorded in `results/SUMMARY.md`.

## 5. Reproduction Commands

Linux / WSL2:

```bash
cd lib && sha256sum -c libmufu_model.a.sha256 && cd ..
make gpu-all TAG=mygpu
```

Native Windows:

```bat
certutil -hashfile lib\mufu_model.lib SHA256     :: compare with lib\mufu_model.lib.sha256
powershell -ExecutionPolicy Bypass -File test\gpu\run_all.ps1 -Tag mygpu -Arch sm_89
```

`summary.txt` contains 10 PASS lines; the sum of `checked` over the steps matches the totals in [`results/SUMMARY.md`](results/SUMMARY.md).
